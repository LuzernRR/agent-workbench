## 用户看到的问题

旧格式虽然包含 Markdown 标记，但层级是：

```md
1. **第一个字段**：值
   - **第二个字段**：值
   - **第三个字段**：值
```

第一个字段被当成整个记录的一级列表项，其他字段却成为它的子项。视觉上层级不对等，复制为
纯文本后更容易退化成“字段：值。字段：值。”的密集段落。单纯要求“使用 Markdown”无法保证
信息结构真正可读。

## 新结构

字段型回答现在使用：

```md
### 1. <模型依据该条已读证据生成的对象或场景短标题>

- **<用户字段 1>**：<模型依据已读证据生成的值>
- **<用户字段 2>**：<模型依据已读证据生成的值>
- **来源链接**：[来源N]

> <模型依据用户当前安全要求生成的简短边界说明>
```

服务端只从当前问题动态提取条数范围、字段名和安全边界，不提供对象、产品、体验、结论或固定
免责声明。短标题、字段值、引用和说明仍由真实 Writer 基于当前 Evidence 生成；前端只用已有
ReactMarkdown 安全渲染，链接和外部图片安全策略没有放宽。

Prompt 版本为 `2026-08-01.v40-markdown-record-hierarchy`。

## 确定性防线

`_explicit_output_issue()` 对字段型记录强制检查：

- 条目数位于用户允许范围，标题编号从 1 连续递增；
- 每条是非空 `### N. ...`，标题不含 `[来源N]`、占位文字或直接复用字段名；
- 标题后必须有空行；
- 每个用户字段按原顺序使用无缩进同级 `- **字段**：值`；
- 不允许字段行内堆叠、旧嵌套列表、额外普通列表、表格或多余段落；
- 来源字段列全该记录实际使用的引用，其他字段中的引用不能被遗漏；
- 用户明确要求非医疗边界时，语义等价说明必须位于 `>` 引用块；“不构成医疗或护肤建议”
  等自然措辞可通过，不再要求固定句式。

格式不合格只会形成结构化 rewrite issue，最多使用已有的一次模型修复机会；服务端不会拼接或
替换自然语言答案。普通直接回答和没有显式字段的搜索回答保持原有灵活生成。
