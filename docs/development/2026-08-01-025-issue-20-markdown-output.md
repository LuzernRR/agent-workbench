# Issue #20：模型 Markdown 字段输出

## 范围

本 Issue 只处理用户明确指定多条记录和字段时的最终回答结构、引用对齐与受控改写。不修改前端
自然语言，不写入防晒答案，不改变小红书登录态、搜索 Provider、Evidence 生命周期或记忆结构。

## 根因

原动态输出合同能提取用户当前问题中的条数范围与斜杠分隔字段，但只要求“逐行包含字段”。
确定性检查也只验证字段是否出现、顺序是否正确，以及“来源链接”后是否有 `[来源N]`。因此模型
把多个字段连续写在一个段落中仍能通过，Workbench 最终显示为难读的密集正文。

同时发现三个相邻问题：

1. 多字段 Markdown 的结构标记占用字符，统一 760 字硬边界会截掉来源或必需免责声明；
2. Writer 会用弱正文凑条数，或把产品名、用户筛选词和常识当成字段证据；
3. 工具调用达到上限时，图会连不需要工具的唯一一次答案改写也一起阻断。

## 修改

### 动态 Markdown 合同

动态合同仍只从当前问题解析字段，不包含任何业务答案。Writer 收到的结构要求为：

- 编号一级列表，每个编号项是一条完整记录；
- 第一字段位于编号项首行，其余字段为缩进子列表；
- 字段名加粗且每个字段独占一行；
- 相邻记录之间保留空行，不改用表格；
- “来源链接”列全该条实际使用的所有 `[来源N]`。

确定性检查同步验证 Markdown 行结构、字段顺序、记录空行和引用集合。旧的行内字段堆叠、把不同
字段拆成不同编号项、缺少引用或来源字段漏列引用都会触发一次 Writer 改写。

### 证据选择与字段语义

Writer/Verifier Prompt 增加领域无关规则：

- 已读来源多于条目下限时，优先选择对用户字段覆盖更完整的正文；
- 只有标题、类别、场景清单或泛化宣称的来源不能用于凑条数；
- 每条记录必须能看出描述的具体对象；分类未说明时保留对象名并如实标注；
- 用户问题中的季节、场景、对象或类别只是筛选条件，不能自动写入某条 Evidence 记录；
- 不得用“产品名暗示”或“可以推断”要求补写正文没有的类型、人群或结论；
- 对象和主要体验有正文支持时，次要字段准确写“正文未说明”是有效记录，不因信息不完整拒绝。

这些规则不包含“黛珂、Dr.G、油敏皮”等答案内容。测试使用另一个“项目名称 / 申请资格 / 截止
日期 / 来源链接”问题验证字段完全来自当前问题，且不会泄漏防晒或医疗措辞。

### 长度与图收尾

普通回答继续使用 760 字交付上限。只有明确字段型记录使用 1100 字上限，动态指令仍要求控制在
1000 字内，给 Markdown 标记、来源和用户要求的结尾保留安全余量。

`TOOL_CALL_LIMIT` 现在是搜索软停止：它禁止新增工具调用，但 Verifier 若只要求改写，仍可使用
现有 Evidence 完成唯一一次 Writer 修复。改写次数最终保持 1，避免以重复模型调用牺牲端到端
响应时间。

Prompt 版本为 `2026-08-01.v39-verifier-missing-field-policy`。

## 测试

新增或更新的确定性覆盖包括：

1. 符合要求的编号、加粗字段、缩进子列表和记录空行通过；
2. 字段行内堆叠、字段拆散和来源字段漏列引用被拒绝；
3. 动态合同使用非防晒字段，不发生领域措辞泄漏；
4. 字段型输出使用 1100 字预算，直接回答仍为 760 字；
5. Verifier 漏判格式时触发一次模型改写；
6. 工具调用到达上限后仍可完成一次无工具改写，并保持工具计数不增加。
