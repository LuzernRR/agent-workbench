# 前端工作台实现

## 1. 当前范围

当前前端是完整可交互的单助手工作台样机，运行于 `http://localhost:3100`。所有接口由 Next.js 本地模拟层提供，用来验证 UI、状态机和事件协议，不包含真实模型和数据库。

## 2. 页面布局

```mermaid
flowchart LR
  LEFT["项目与会话"] --> CENTER["对话与输入"]
  CENTER --> RIGHT["计划与成果工作区"]
```

- 左栏：新建会话、项目、会话列表、重命名、移动和删除。
- 中栏：标题、消息、运行过程、审批、引用、输入和停止。
- 右栏：计划、成果、文件、网页、代码和日志。

桌面端三栏可调整宽度；窄屏工作区改为右侧抽屉；移动端隐藏左栏并保留新建与工作区入口。

## 4. 状态分层

### 服务端权威状态

由 TanStack Query 和 `useAgentThread` 管理：

- 项目和会话列表。
- 会话快照。
- 消息和运行状态。
- 计划、工具、审批、成果、文件和日志。
- 模型和工具目录。

### 界面状态

由 Zustand 管理：

- 当前模型。
- 当前工作区标签。
- 选中的成果和文件。
- 工作区全屏状态。
- 待发送附件。

服务端事实不能只写 Zustand。页面刷新后仍需存在的数据必须来自快照或事件。

## 5. 新会话流程

新会话默认不创建空数据库记录。用户第一次发送时：

1. 输入内容和草稿附件保留在界面状态。
2. 创建会话。
3. 上传附件并得到附件标识。
4. 用当前模型和工具配置创建运行。
5. 清理草稿附件。
6. 刷新会话列表并切换到新会话。
7. 按运行事件开始流式展示。

提交 Promise 使用引用去重，快速重复点击不会创建两个会话。

## 6. 会话切换与防闪屏

切换时必须满足身份一致性：

- 快照中的 `thread.id` 等于当前选择。
- reducer 状态中的 `threadId` 等于当前选择。
- 请求仍在获取或身份不一致时显示固定骨架。
- 骨架不接收旧线程状态，因此不会泄露上一会话内容。
- 工作台外壳不卸载，避免整屏背景闪烁和面板宽度重置。

消息列表 key 使用稳定消息标识，不能使用数组下标。

## 7. 事件归并

客户端按 `itemOrder` 保存时间线顺序，`items` 保存实体。归并要求：

- 事件按 `seq` 处理。
- 重复事件幂等。
- `message.delta` 只追加到对应消息。
- `message.completed` 用完整文本修复丢失增量。
- 工具开始、进度和结束更新同一工具项。
- 计划使用完整快照。
- 成果和文件按标识与版本更新。
- 运行终态写入独立状态表，历史消息不因新运行改变。

文字增量通过打字队列平滑显示，非文字事件立即处理。队列要支持清空、停止和完整消息重置。

## 8. 输入框交互

| 操作 | 行为 |
| --- | --- |
| 输入文字 | 输入框随内容增高，达到上限后内部滚动 |
| Enter | 发送 |
| Shift + Enter | 换行 |
| 粘贴图片或文件 | 加入待发送附件 |
| 拖入文件 | 加入待发送附件 |
| 附件按钮 | 选择图片或文档 |
| 模型按钮 | 打开中文模型列表并选择 |
| 发送按钮 | 创建运行，空输入时不可用 |
| 停止按钮 | 取消当前运行并保留已有内容 |
| Escape | 运行时停止 |

限制：每条消息最多十个附件，单个附件最多 20 MB。真实服务端必须再次校验，前端限制只用于即时反馈。

## 9. 消息交互

- 用户消息靠右、使用轻灰背景。
- 助手消息使用无卡片正文，避免卡片套卡片。
- 工具执行是紧凑可折叠行，默认显示动作和耗时。
- 审批作为时间线中的独立操作行。
- 完成的助手回复可复制。
- 最新且已终止运行的用户消息可编辑并重新发送。
- 图片可打开大图预览。
- 引用显示短标签并使用安全地址。
- 流式输出使用细光标，不使用闪烁整块骨架。

## 10. 工作区揭示规则

右侧工作区默认折叠，以下事件到达后自动打开：

- 首次出现或更新计划。
- 首次出现或更新成果。

打开方式：

- 桌面端扩展右侧面板。
- 窄屏和移动端打开右侧抽屉。
- 已有会话加载时不自动打开，避免切换会话时打断用户。

标签只显示有内容的类型，避免空标签和说明性占位。

## 11. 视觉规则

- 字体统一使用系统中文无衬线字体栈。
- 基础字号 15px，正文行高 1.7，代码 13px。
- 对话和输入区最大宽度 900px。
- 主背景、侧栏、内容和工作区只使用轻微明度区分。
- 主要层级依靠间距、字重和分隔线，不堆叠阴影和描边卡片。
- 列表文字完整换行，不用截断和省略符号。
- 首页招呼语大于普通正文，保持单句。
- 动画限制在 150 到 180 毫秒的颜色和轻微缩放。
- 遵循 `prefers-reduced-motion` 时关闭非必要动画。

## 12. 中文化规则

界面显示：

- “项目”“会话”“模型”“工作区”“计划”“成果”“文件”“网页”“代码”“日志”。
- 模型使用“旗舰模型”“均衡模型”“快速模型”这类产品名称。
- 时间单位使用“分”“秒”。
- 错误通过中文映射，不显示内部错误码、运行时类名和堆栈。

内部类型、API 路径和代码标识可以使用英文，但不能直接透传到界面。

## 13. 无障碍

- 图标按钮必须有中文 `aria-label` 和 `title`。
- 弹窗有标题、说明、取消和明确动作。
- 菜单、标签页和审批支持键盘。
- 焦点样式清晰，不能只依赖颜色。
- 状态变化使用适度的 `aria-live`，文本增量不重复朗读整个消息。
- 颜色对比满足常规文本和控件要求。
- 可拖动的会话同时提供“移入项目”菜单，不能只依赖拖拽。

## 14. 错误与加载状态

- 首屏和侧栏使用结构稳定的骨架，尺寸接近真实内容。
- 会话切换显示会话骨架和顶部加载状态。
- 项目、会话、模型、附件和运行错误各自局部展示。
- 错误不覆盖可用的旧数据。
- 每个可恢复错误提供重试或再次执行入口。
- 错误横幅可关闭，但新错误仍会再次出现。

## 15. 自动化测试

### 单元测试

- 事件 reducer。
- 打字队列。
- 错误中文化和安全链接。
- Markdown 清理和链接安全。
- 成果去重与审核状态。

### Playwright 核心流程

1. 新会话欢迎页和大招呼语。
2. 模型选择。
3. 发送并观察流式文本。
4. 工具执行展开与收起。
5. 计划自动打开工作区。
6. 停止运行。
7. 审批允许和拒绝。
8. 成果、文件、代码和日志切换。
9. 创建、重命名和删除项目。
10. 重命名、移动和删除会话。
11. 快速切换会话不泄露旧内容。
12. 桌面、窄屏和移动端无水平溢出。

### 视觉审计

- 1440 × 960 桌面。
- 1024 × 768 窄屏。
- 390 × 844 移动端。
- 空会话、运行中、审批中、完成、失败和长内容。
- 中文长项目名、长会话名、长文件名和代码块。

## 16. 正式后端接入

前端只依赖公开 API 与事件协议。接入正式服务端时：

1. 保持 `/api/v1` 请求和事件类型不变。
2. 配置服务端来源或由 Next.js 同源代理转发。
3. 移除生产构建中的模拟处理器。
4. 使用真实鉴权和短时文件地址。
5. 用契约测试比较模拟层和正式服务端响应。
6. 先小流量启用真实运行，保留模拟测试夹具。

不在 React 组件中直接解析 LangGraph 内部事件。服务端事件映射层必须保持前端协议稳定。
